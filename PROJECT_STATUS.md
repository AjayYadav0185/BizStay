# BizStay — Go-Live Status, Remaining Work & Client Pricing

> Updated: 25 Sep 2026 · Branch main · Laravel 13 + Filament 3 + SQLite (MySQL/MAMP-ready) + Flutter app (Android/iOS). Verdict: YES — ready to go live for a single Gurgaon PG / PG+Hotel TODAY, web + phone. See S1, then S4.

## 1. Are we ready to go? — YES, with one honest boundary. Daily PG ops (check-in, monthly invoice, UPI/cash Collect with UTR, checkout settlement, P&L) all work in /admin, and the same operations now run from the BizStay phone app (manager + tenant roles). PG+Hotel mix works since 25 Sep: stay_type pg/hotel, nightly_rate, GST slab 12pct up to Rs 7,500/night and 18pct above (0pct on PG rent), GST line + GSTIN + UPI on the printed invoice (tested: 4 x Rs 1,499 = Rs 5,996 + Rs 719.52 GST). Boundary: ONE building per install — no multi-property switcher and no online payment gateway yet (tenants see the UPI ID and pay peer-to-peer; the office records the reference). Each building gets its own install/subdomain.
Go-live checklist for client 1: (1) migrate fresh + seed, (2) change admin password, set property name/code, GSTIN, UPI ID, 12:00/11:00 times, (3) enter real rooms + rates (single ~Rs 18k, double ~Rs 10k, triple ~Rs 8k), (4) php artisan test = 14 passed, (5) cron schedule:run + daily DB dump, (6) hand out the app: manager login + one tenant login per resident (phone number + password).

## 3. The phone app (Flutter, added 25 Sep). One app, two roles — the API decides the surface after sign-in. Manager signs in with email, tenant with the mobile number on their PG record. Manager tabs: Today (occupancy, beds sold, month collected/expenses/profit, dues, open complaints, open leads), Rooms (every bed + PG rent per bed next to the hotel nightly tariff), Residents (search by name/number, KYC state, masked Aadhaar, dues + Stays list with PG/Hotel chips), Billing (outstanding/overdue/paid queues with a running total and a Collect-payment sheet for UPI/cash/netbanking/card/cheque, part payment supported), Ops (complaint tickets with SLA state, lead pipeline, log-a-complaint form). Tenant tabs: My stay (bed, dues, next bill, property UPI ID to copy, check-in/out times, payment history), Bills (invoice history with the GST line on hotel folios), Help (own complaints + raise one). Backend added the same day: routes/api.php with 13 Sanctum-token endpoints (login, me, logout, dashboard, rooms, guests, bookings, invoices, invoice collect, me/stay, complaints GET+POST, inquiries) in app/Http/Controllers/Api; users gained role (manager|tenant) + guest_id; DemoSeeder now creates the 3 staff logins and one tenant login per resident (phone + password). Two real bugs found and fixed by this work: Property::monthlyPnL() type-hinted an unimported Carbon (the API dashboard 500'd), and LoginScreen read an InheritedWidget in initState (crashes every debug build). Gates: Laravel 14/14 tests, Flutter 28/28 tests, flutter analyze clean, debug APK builds.
